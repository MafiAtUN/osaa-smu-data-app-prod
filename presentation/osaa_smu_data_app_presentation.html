Core Capability

AI workflow for hypothesis testing in minutes

This is the key contribution: frame a hypothesis, fetch the right data live, test relationships, and revise instantly if data quality is weak.

1

Define Hypothesis

Example: “Higher conflict correlates with lower GDP growth”.

2

Plan Metrics

LLM + rules map query to series IDs and scope (country/region).

3

Fetch Data Live

Cache-first retrieval from WB, ACLED, SDG, UIS, UN Data APIs.

4

Test + Diagnose

Correlation/trend checks with overlap and sparse-data warnings.

5

Visualize + Iterate

Prompt chart updates and re-run revised assumptions quickly.

Interactive hypothesis cycle

H
State hypothesis

Directly in natural language, no scripting needed.

T
Test with joined data

Automatic merge by ISO mapping and year keys.

R
Refine and retest

Suggested proxies/date shifts when data is missing.

Example prompt chain

1) “For Algeria 2005–2024 compare conflict events and GDP.”
2) “Now test lag of 1–3 years and show robustness without outlier years.”
3) “Create a policy-brief chart with caution notes.”

Implementation Guide

How to run locally for free (GitHub + Ollama)

This setup is ideal for demonstrations, prototypes, and cost-controlled deployments.

Step-by-step setup

1
Clone repo

Pull the latest code from GitHub.

2
Create virtual env

Install dependencies from requirements.

3
Install and run Ollama

Download local model and keep service running.

4
Configure .env

Point LLM endpoint to local Ollama, add API keys for data sources.

5
Run Streamlit app

Launch and verify Cross-Source + Hybrid Sync pages.

Command reference

git clone <your-repo-url> cd osaa-smu-data-app-prod python -m venv .venv source .venv/bin/activate pip install -r requirements.txt # install ollama from https://ollama.com/download ollama pull llama3.1:8b ollama serve # in .env (example) # LLM_PROVIDER=ollama # OLLAMA_BASE_URL=http://localhost:11434 # OLLAMA_MODEL=llama3.1:8b streamlit run app/main.py

For production, add reverse proxy, auth, and scheduled sync runs.
