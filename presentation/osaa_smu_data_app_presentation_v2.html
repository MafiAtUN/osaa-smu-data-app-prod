The SMU Data App Solution

From question to tested evidence in under 5 minutes

One natural-language query triggers live API retrieval, automatic joins, diagnostic checks, and explainable outputs — all in a single session.

Zero hallucination guarantee

AI only analyzes data pulled live from authoritative APIs. It cannot invent statistics — every figure is fetched, not generated. The LLM interprets; the data speaks for itself.

No spreadsheet uploads needed

Unlike Copilot or ChatGPT, there is no "upload your CSV first" step. The app handles retrieval, joining, and normalization automatically via API.

Iterate, revise, retest instantly

Add a country, change the date range, switch an indicator — the system re-runs the analysis. No redownloading, no re-joining. Hypothesis testing becomes conversational.

Privacy and Data Sovereignty

Working with sensitive information safely

Some UN analyses involve confidential operational data, pre-publication figures, or politically sensitive indicators. The local LLM mode ensures nothing leaves your machine.

The two modes explained

☁
Cloud LLM (Azure OpenAI)

Best for: public indicator analysis, standard policy briefs, cross-country SDG work. Uses Azure Government-compliant endpoints. Models: GPT-4o, GPT-5, GPT-4.1.

🖥
Local LLM (Ollama — free)

Best for: mission-critical, pre-publication, or politically sensitive data. Model runs entirely on your laptop or UN server. Zero external API calls. Zero cost.

⚡
Hybrid (default recommended)

Ollama for routine query planning; cloud for high-stakes reasoning steps. Reduces cost by ~60% while maintaining quality.

Technical Architecture

Python · Streamlit · DuckDB · Multi-LLM

Built for reliability, auditability, and cost-efficiency. Every layer is designed to be swappable — switch LLMs, add data sources, or deploy locally or on Azure.

🖥
Streamlit UI Layer

Rapid interactive interface — pages, widgets, charts, export buttons. No front-end framework needed.

🐍
Python Services Layer

Query planner, API connectors, join engine, diagnostics, sync scheduler. Clean separation from UI.

🤖
Multi-LLM Layer

Azure OpenAI (GPT-4o/GPT-5), local Ollama (Llama, Qwen). LangChain for conversation history and message routing.

🦆
DuckDB Storage Layer

Local analytics-grade cache, metadata registry, refresh logs, vector embeddings. No server required.

🌐
API Connector Layer

Modular adapters for each data source: World Bank, ACLED, SDG, UIS, UN Energy. Cache-first with live fallback.

Tech stack at a glance

Language: Python 3.10+ UI: Streamlit (rapid analytics UI) Database: DuckDB (local OLAP, cache, vectors) AI Layer: LangChain + multi-provider factory Cloud: Azure OpenAI (GPT-4o, GPT-5) Local: Ollama (Llama 3.1, Qwen 2.5, etc.) APIs: World Bank · ACLED · UN SDG UNESCO UIS · UN Energy Deploy: Docker → Azure App Service (or: git clone + streamlit run) Auth: Streamlit secrets + .env fallback CI/CD: GitHub Actions → Azure
